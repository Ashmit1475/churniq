# Power BI dashboard — build guide

A `.pbix` file is a binary format that can only be authored in Power BI Desktop (Windows), so it can't be generated by script. Everything the dashboard needs is already produced by the pipeline — this guide is the 60–90 minutes of clicking that turns it into the three-page report.

**Before you start:** run the pipeline so the `predictions` table exists.

```
python src/make_sample_data.py
python src/ingest.py
python src/train.py
python src/predict.py
python src/evaluate.py
```

---

## 1. Connect to the data

**Preferred — live SQL connection.** This is the detail that makes it a dashboard rather than a screenshot: the report re-queries when you re-run the pipeline.

- SQLite: install the [SQLite ODBC driver](http://www.ch-werner.de/sqliteodbc/), then **Get Data → ODBC**, pointing at `data/churniq.db`.
- Postgres (Supabase/Neon): **Get Data → PostgreSQL database**, host/database from your connection string. Use **Import** mode.

**Fallback — CSV.** **Get Data → Text/CSV** on `reports/scored_customers.csv`. Works everywhere, but you must click Refresh after each pipeline run. If you use this, say so in your README rather than implying a live connection.

Load these tables: `predictions` (main), `customers`, `billing`. Also load `reports/churn_drivers.csv` and `reports/threshold_curve.csv` for page 3.

## 2. Model relationships

In **Model view**, create:

- `customers[customerID]` → `predictions[customerID]` (one-to-one, single direction)
- `customers[customerID]` → `billing[customerID]` (one-to-one)

Mark `predictions` as the fact table you build measures against.

## 3. DAX measures

Create these in a dedicated `_Measures` table (**Home → Enter Data**, name it `_Measures`, delete the placeholder column). Keeping measures separate from data tables is a small thing that reads as competence.

```dax
Total Customers = DISTINCTCOUNT(predictions[customerID])

High Risk Customers =
CALCULATE([Total Customers], predictions[risk_flag] = "High")

High Risk % = DIVIDE([High Risk Customers], [Total Customers])

Avg Churn Probability = AVERAGE(predictions[churn_probability])

Revenue at Risk = SUM(predictions[revenue_at_risk])

Total Customer Value = SUM(predictions[customer_value])

Revenue at Risk % = DIVIDE([Revenue at Risk], [Total Customer Value])

Monthly Recurring Revenue = SUM(predictions[MonthlyCharges])

-- Retention campaign economics. Change the two constants to match config.yaml.
Offer Cost = 60
Acceptance Rate = 0.30

Campaign Cost = [High Risk Customers] * [Offer Cost]

Expected Revenue Saved =
SUMX(
    FILTER(predictions, predictions[risk_flag] = "High"),
    predictions[revenue_at_risk]
) * [Acceptance Rate]

Campaign Net Benefit = [Expected Revenue Saved] - [Campaign Cost]

Campaign ROI = DIVIDE([Campaign Net Benefit], [Campaign Cost])

-- Model quality, computed live from the scored table
Actual Churners = CALCULATE([Total Customers], predictions[actual_churn] = "Yes")

True Positives =
CALCULATE([Total Customers],
    predictions[risk_flag] = "High", predictions[actual_churn] = "Yes")

False Positives =
CALCULATE([Total Customers],
    predictions[risk_flag] = "High", predictions[actual_churn] = "No")

False Negatives =
CALCULATE([Total Customers],
    predictions[risk_flag] = "Low", predictions[actual_churn] = "Yes")

Precision = DIVIDE([True Positives], [True Positives] + [False Positives])

Recall = DIVIDE([True Positives], [True Positives] + [False Negatives])

F1 Score = DIVIDE(2 * [Precision] * [Recall], [Precision] + [Recall])
```

Format `Revenue at Risk`, `Campaign Cost` and `Campaign Net Benefit` as currency with 0 decimals; `High Risk %`, `Precision`, `Recall` as percentages.

## 4. Page 1 — Executive overview

Purpose: a manager understands the churn problem in ten seconds.

| Element | Visual | Fields |
|---|---|---|
| KPI row | 4 × Card | `Total Customers`, `High Risk %`, `Revenue at Risk`, `Avg Churn Probability` |
| Risk distribution | Stacked column | Axis `risk_band`, Value `Total Customers` |
| Churn by contract | Clustered bar | Axis `Contract`, Value `Avg Churn Probability` |
| Risk × tenure | Matrix w/ conditional formatting | Rows `Contract`, Columns `tenure_bucket`, Values `Avg Churn Probability` |
| Top drivers | Bar | From `churn_drivers` — Axis `feature`, Value `importance` |
| Slicers | `Contract`, `InternetService`, `tenure_bucket` | |

Sort `risk_band` correctly: select the column, **Column tools → Sort by column**, and add a numeric order column if the alphabetical order (Critical, High, Low, Medium) bothers you — it should.

## 5. Page 2 — Customer risk list

Purpose: a retention agent gets a call list.

- **Table** with `customerID`, `churn_probability`, `risk_band`, `MonthlyCharges`, `tenure`, `Contract`, `revenue_at_risk`, `top_risk_reasons`. Sort descending by `churn_probability`.
- Apply **conditional formatting → data bars** on `churn_probability`, and a red-amber-green **background colour** scale on `revenue_at_risk`.
- **Slicers:** `risk_band`, `Contract`, `PaymentMethod`, plus a numeric range slicer on `MonthlyCharges`.
- **Cards** above the table showing `High Risk Customers` and `Revenue at Risk`, so they respond to the slicers.
- Add a **Top N filter** (top 500 by `churn_probability`) so the page stays fast.

The `top_risk_reasons` column is the differentiator here — it comes from SHAP, and it turns "customer 4821 is 0.84 risk" into something an agent can act on.

## 6. Page 3 — Model performance

Purpose: show you understand the model's limits. Including this reads as maturity; hiding it reads as inexperience.

- **Cards:** `Precision`, `Recall`, `F1 Score`, and a text box stating the tuned threshold and test ROC-AUC from `reports/metrics.json`.
- **Confusion matrix:** a Matrix visual with `actual_churn` on rows, `risk_flag` on columns, `Total Customers` as values.
- **Threshold curve:** line chart from `threshold_curve` — Axis `threshold`, Value `expected_value`. Add a constant line at your chosen threshold via the Analytics pane.
- **Images:** insert `reports/figures/roc_curve.png` and `reports/figures/pr_curve.png`.
- **Text box** explaining the threshold choice in one sentence: why 0.5 was rejected and what the tuned value optimises for.

## 7. Polish

- **Theme:** View → Themes → pick one and stay consistent. Default blue is fine; inconsistent colours are not.
- Give every visual a real title ("Average churn probability by contract type", not "Average of churn_probability by Contract").
- Turn off the visual header in the Format pane for a cleaner look.
- Set page size to 16:9 and align visuals to the grid.
- Add a small text box on page 1 crediting the data source and noting whether it's the real Kaggle dataset or synthetic sample.

## 8. Publish for the README

1. Save as `dashboard/ChurnIQ.pbix` and commit it.
2. Screenshot all three pages at full resolution → `reports/figures/dashboard_p1.png` etc.
3. Record a 30–60 second walkthrough and convert to GIF (ScreenToGif is free) → embed at the top of the README.

**Do not use Publish to Web** to embed the report elsewhere. It makes the report accessible to anyone with the link, with no authentication, and is disabled in most corporate tenants. Screenshots plus the committed `.pbix` are the standard way to show Power BI work in a public portfolio.
